Intent processing and routing boundary

Voice Route Bot

My contribution. I scoped the Berlin travel prototype and developed the voice and text intent-processing flow.

Design decision. I used the model to extract a typed request. Application code validates the request and saves a summary for the user to check before the planned routing step.

Telegram → voice transcription or text → LLM extraction → typed validation → saved request and summary

Illustrative input. “Visit Museum Island for two hours, avoid the subway, and get me home by 10 pm.” The expected intent captures the destination, activity duration, excluded mode, and arrival deadline.

Room perception · Isaac Sim / NVIDIA Omniverse

Room Digital Twin

My contribution. I developed a staged approach to integrating RGB-D observations, perception proposals, protected state updates, and replay. I extended the evaluation workflow with controlled scenes in Isaac Sim / Omniverse.

Architecture. Capture and calibration feed frame admission and pairing. Perception proposes changes, independent checks validate observable support, and protected transactions update persistent room state.

Isaac Sim / Omniverse scene → calibrated RGB-D capture → verified transfer → local replay → protected state update → continuity scoring

Demonstrated. The camera-independent software passed its scoped acceptance checks. A clean-checkout simulation run completed all 13 workflow stages, processed 450 captures per episode, and reproduced the same outcome across both episodes.

Lesson from the pilot. Identity recovery remained unscorable because the retained episodes had no accepted person entry before occlusion. A later doorway-origin path passed its declared entry controls. On the retained episodes, the measured person-model fit still prevented a commit.

Open work. Resolve the mismatch between the simulated humanoid and the declared person model, then evaluate identity recovery on eligible episodes. Physical sensor and real-room qualification remain pending in the portfolio record.

World models · learning and evaluation

Crafter World Model

Project. An experimental system investigating how learned environment predictions support decision-making in Crafter. Wood collection provides a bounded task for examining movement, orientation, blocked actions, reward prediction, and sequences of actions.

My contribution. I directed the decomposition into environment interaction, data collection, training, evaluation, and diagnosis, coordinating implementation with coding agents. I defined task boundaries and acceptance criteria and used observed failures to shape follow-up investigations.

Architecture

The workflow connects an environment interface and explicit observation/action contracts to transition collection, replay data, learned dynamics and reward components, and policy or planning evaluation. Recurrent world-model experiments use checkpoint and trace infrastructure to support diagnosis and recovery.

Environment interaction → transitions and replay → model training → policy evaluation → traces and diagnosis

Design decision. Evaluate environment prediction and task performance as separate measurements. Inspect which situations enter replay and whether the policy learns to choose useful action sequences.

What the work revealed

Development runs exposed a gap between immediate harvesting and tasks requiring a preceding action. This made action sequences and the coverage of relevant situations in training data central diagnostic questions.

AI lessons. A task-success measure needs to reflect the intended behavior. Model error, reward prediction, and policy decisions each contribute different evidence when investigating a failed task.

Agentic development. Precise contracts help coding agents work across collection, replay, training, and evaluation. Integration checks need to cover reset behavior, sequence construction, source identity, and resource accounting.

Solo-development challenge. Coordinating the environment, learning system, evaluation, and infrastructure creates a verification bottleneck. Small reproducible failure cases and inspectable traces help determine the next investigation.

Current scope. Exploratory research with bounded task competence. The next evaluation questions concern sequence learning, retention of earlier skills, and generalization.
